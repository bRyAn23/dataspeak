## How these practices affect reliability, consistency, maintainability and recovery

**Reliability.** Health-gated start-up (`depends_on: service_healthy`), restart policies, a worker that drains its current job before stopping, and a deploy script that fails loudly when the health endpoint does not answer reduce the chance of serving a broken release. The queue and scheduler run as separate processes, so a long analysis cannot block web requests (NFR-PER-001), and bounded Redis memory with a TTL-first eviction policy keeps the small instance stable.

**Consistency.** Because development and production start from the same Dockerfiles, lock files and Compose definitions, the difference between the two environments is confined to one environment file. Summers (2020) describes configuration management as the discipline of identifying, controlling and auditing the items that make up a release; here those items are the committed Dockerfiles, Compose files, lock files and templates at a known commit, and the image bytes moved to the server are the ones that were built and tested. Bennett (2024) likewise stresses that controlled baselines and environment configuration prevent the "works on my machine" class of failure, which is what the separated env files and `npm ci` discipline address.

**Maintainability.** Settings such as the LLM provider, upload limits, proxy trust and CORS origins are environment switches rather than code changes, and the three services keep separate dependency manifests and test suites, so a change in one can be built and verified in isolation. The health endpoint and route list give a quick, scriptable way to confirm a deployment.

**Deployment recovery.** Migrations run before traffic is switched, the previous image remains on the host until pruned, and the stack can be re-created from the repository plus the env file. The gaps are equally clear: without versioned image tags, an automated pipeline and externalised secrets, recovery depends on an operator rebuilding a known commit, which is slower and more error-prone than promoting a tagged artefact. Closing those gaps is the planned next step rather than a current capability.
