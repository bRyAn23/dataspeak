# Academic Evidence Summary: System Testing Across Three Rounds (Unit 7)

University of the People, MSIT 5910-01 Capstone Project. Data Speak. Prepared 2026-10-16. Every figure below is taken from the execution records in `docs/testing/unit7/` (Round 1, 2026-10-15), `docs/testing/unit7/retesting/` (Round 2, 2026-10-16 morning) and `docs/testing/unit7/round3/` (Round 3, 2026-10-16 evening). Earlier failures are reported as they occurred; the final results do not imply that the earlier defects did not exist.

**1. Round 1: initial system testing and defect discovery.** System testing of commit `e5ecc93` on the local development stack executed 8 integration cases, 15 system cases (including retests), 4 regression suites, 3 performance scenarios and a 12-criterion investigator-led acceptance inspection. After five harness errors were triaged and corrected, all executed cases passed, yet the inspection of production reports and the Unit 6 usability concerns yielded eight product defects: one Major (DEF-01, a claim with doubled braces passed validation and rendered literal braces), three Medium (DEF-04 queue contention from background translations, DEF-06 CI failure from unpinned dependencies, and the DEF-09 condition that would surface later) and Minor presentation, wording and accessibility issues (DEF-02, 03, 05, 07, 08). The baseline regression counts were 49 analytics tests, 148 backend tests and 28 frontend tests, with 33 golden-reference assertions reproduced exactly.

**2. Root-cause investigation and corrective actions.** Each defect was traced to a specific mechanism before any change: a validator that inspected only well-formed placeholder tokens; a report assembler that kept a repeated headline; a statistic label passed through to business text; one worker serving both user-facing and background queues; an unpinned schema generator; a disabled control without explanation; colour tokens and link sizes below WCAG thresholds; a layout that placed the data-quality warning below the fold. Corrections were committed one per defect (`0b33df0` to `524842f`) with six new unit tests, a dedicated translations worker, dependency pins and interface changes.

**3. Round 2: post-fix verification.** Retests RT-01 to RT-08 reproduced each corrected behaviour on the real stack; two retests failed on first execution for environmental reasons (a worker image missing development dependencies; one remaining low-contrast badge) and passed after same-session repairs (RT-04b, RT-07b). The suites grew to 154 backend tests and remained green; the CI analytics job was reproduced in a container matching GitHub Actions. The full harness was re-run: 20 of 23 cases passed at the first attempt and three failed because the narrative request timed out while the single local model was serving a translation job.

**4. Discovery and resolution of DEF-09.** That failure was registered as DEF-09 and deferred in Round 2 because its remedy needed its own cycle. Round 3 established the cause with measurements: Ollama processes one request per model at a time (a probe showed two concurrent requests completing at 0.83 s and 1.68 s), the client timeout includes server-side queueing, and the Round 2 worker split allowed translation and narrative requests to reach the model simultaneously. The correction (`57b7bce`) is an application-side model-access coordinator: a TTL lock released in `finally`, bounded waits for every request class, bounded priority for user-facing requests over background translation (which can therefore never starve), a distinct `AI_BUSY` failure that sends nothing, and a single delayed retry of the report job for that case only. Memory was measured before deciding not to raise the server's parallelism. The coordinator is inactive for the production API provider, where the condition cannot occur.

**5. Round 3: final verification.** Eight scheduling unit tests exercise the lock logic with a faked model; ten real-model scenarios exercised the actual stack. The contention scenario that failed in Round 2 passed in every run: thirteen narratives generated under concurrent translation load with no timeout, coordinated waits of at most 29 s, controlled behaviour when the model was unreachable or timed out, graceful worker restart with a job in flight, complete background translation afterwards and unchanged deterministic values. Round 3 also had a failure of its own: a test script left the default-queue worker stopped for 82 minutes, so eleven harness cases, the defect retests and one performance scenario failed in the first attempt. The investigation (preserved with the failed artefacts) traced it to a harness sequencing error exposing a real operational defect, DEF-10: the worker images lacked the `pcntl` extension, so workers ignored the stop signal and were killed after the 120 s grace period. DEF-10 was fixed (`c68be35`) with a build-time guard, and every affected case was re-executed and passed. Three automated pass/fail verdicts in new scripts were found to be criterion errors and are reported with the raw evidence that supports the corrected verdict.

**6. Regression testing and numerical correctness.** At the final commit the suites report 49 analytics tests (93 % statement coverage), 162 backend tests with 955 assertions, 28 frontend tests, clean lint, format and type checks and a successful production build. The 33 golden-reference assertions (26 numeric) reproduce exactly in all three rounds; the deterministic layer was not changed by any Round 3 correction. Hosted GitHub Actions ran on the pushed commit and all four jobs succeeded, which also closes the hosted-verification gap left for DEF-06 in Round 2.

**7. Performance and stability.** FastAPI direct latencies are unchanged within run-to-run noise (analyze of 10,000 rows 0.29 s in Round 1, 0.31 s in Round 3). Profiling through the queue now takes 20–31 s when a translation batch occupies the model, compared with 12–14 s on an idle model and 73 s behind the Round 1 backlog; this is the designed trade-off, bounded by one translation batch. Narrative generation on the local 8 B model takes about two to three minutes; a second narrative queued behind a first completes in about five. No thresholds were defined in any round and none is claimed to be met; the figures describe a developer laptop, not production.

**8. Outstanding defects and limitations.** No product defect remains open on the development stack. Limitations: production behaviour with the Claude API after these changes is not yet demonstrated because the production deployment is pending network access; acceptance is investigator-led, with no real business users or assistive-technology sessions; the local model's Burmese output quality is a known model limitation; the reported durations depend on the host.

**9. Reliability and quality evaluation.** Across three rounds the system showed the properties the design claims: calculations are deterministic and reproducible, the AI layer only interprets stored evidence and fails truthfully when it cannot run, validation keeps unsupported statements out of reports, and failures of the analytics service, the model or a worker end in controlled states rather than false successes. The rounds also showed the value of preserving failures: the Round 2 timeout led to DEF-09, and the Round 3 harness failure led to DEF-10, both of which would otherwise have reached operations undetected. The evidence package is therefore judged sufficient for Part A (system testing and documentation), supportive for Part B (the maintenance plan can cite the verified fixes, the operational findings and the pending deployment step) and adequate for the results chapter of Part C, provided the production limitation and the absence of real-user acceptance are stated as they are here.
